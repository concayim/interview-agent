# Interview Copilot 需求文档

文档版本：`v0.3.0`

更新日期：`2026-06-24`

## 1. 产品目标

提供一个可扩展到多行业的桌面端模拟面试与学习助手。当前以计算机行业为首个领域：用户上传简历后，系统理解其技术栈，按领域 Skill 和面试官风格 Skill 发起有标准答案的面试；每场结束后，用户可以复盘，并将题目沉淀到可检索知识库。

核心价值是“可练习、可解释、可复盘”，而不只是与大模型闲聊。

## 2. 目标用户

- 正在准备后端、基础架构或综合研发岗位的工程师；
- 希望练习 Golang、Java、Python、C++ 技术表达的候选人；
- 希望根据个人简历进行针对性提问的用户。
- 希望从权威文章、课程和视频持续学习，并建立个人学习清单的用户。

## 3. 用户流程

1. 用户进入准备页，可上传 PDF 或 DOCX 简历。
2. 系统读取附件文本，显示文件状态和识别出的技术关键词。
3. 用户选择行业/领域 Skill、面试官风格 Skill、难度、题目数量并填写称呼。
4. 用户可选择把计算机基础公共库混入语言专项面试。
5. 风格化面试官先邀请用户进行 1–2 分钟自我介绍；该阶段记录内容但不计分。
6. 系统综合领域、难度、简历关键词和自我介绍中的技术关键词排序题目，并把本次出题记录到对应知识库。
7. 面试官用简历或介绍中的相关经历自然引出主问题；用户回答后连续追问 2–3 轮。
8. Eino Agent 或本地评分器按所选风格评价技术回答，完成追问后进入下一主问题。
9. 最后一题完成后生成包含自我介绍记录的复盘报告。
10. 用户可在知识库检索/新增 QA，也可在学习中心抓取并选择权威内容。

## 4. 功能需求与验收

### FR-01 附件上传与解析

- 支持 `.pdf`、`.docx`，单文件不超过 10 MB。
- 服务端根据扩展名选择解析器，不接受其他格式。
- 解析得到的文本至少 20 个字符；无法读取的扫描版 PDF 给出明确提示。
- 原始临时文件在解析完成或失败后删除。
- 成功响应包含文件名、字符数、内容预览和最多 18 个技术关键词。

验收：上传含 Go、Redis、Docker 的 DOCX 后，响应中能看到对应关键词；上传 TXT 返回 `415`。

### FR-02 简历关键词

- 识别编程语言、框架、数据库、中间件、云原生、工程实践等关键词。
- 关键词按出现次数排序并去重。
- 关键词用于题目相关性排序，不影响题库的标准答案。

### FR-03 技术题库

- 第一版支持 Golang、Java、Python、C++。
- 每种语言至少 6 道题，覆盖基础、进阶、挑战三个难度。
- 每道题必须包含题目、标准答案、关键点和标签。
- 作答前的接口不得返回标准答案和关键点。
- 计算机基础公共库至少提供 6 道题，可混入任意计算机语言 Skill。

### FR-04 面试对话

- 正式技术问题前必须先进行一次自我介绍；邀请语由面试官 Skill 提供，自我介绍不计分。
- 自我介绍完成后，系统必须综合简历关键词和介绍中识别的技术关键词重新排序已选问题。
- 与简历或介绍关键词匹配的题目应显示自然的上下文引导语，使问题与候选人经历形成连续对话。
- 用户可以用数字输入自由设置主问题数量，最少 1 题、接口上限 20 题，实际数量不超过当前知识库筛选结果。
- 当前混合难度单语言最多 6 道主问题，启用公共库后最多 12 道；专项难度分别最多 2/4 道。
- 每个主问题必须追问 2–3 轮；具体轮数由面试官 Skill 声明。
- AI 追问必须参考主问题、此前回答、标准答案关键点和面试官风格，不能泄露标准答案或重复主问题。
- 模型不可用时必须自动生成风格化本地追问，不得中断面试。
- 显示主问题进度、追问轮次、总计时、题号和题目标签。
- 空回答不能提交，单次回答不超过 8,000 字符。
- 同一轮重复提交不得产生两条答案记录。

### FR-05 模型接入

- 用户可以配置 API Key、Base URL、Model 和启用状态。
- 使用 Eino OpenAI ChatModel 对接 OpenAI-compatible API。
- 模型评价必须返回 0–100 分、总结、优点和改进项。
- 模型未配置、超时或返回异常时，面试继续并使用本地关键点评分。
- 提供连接测试接口。

### FR-06 面试复盘

- 显示综合得分、作答数量、总耗时、优点和下一轮重点。
- 展示本场自我介绍原文，并明确标记为不计分。
- 每题显示用户回答、标准答案、关键点、分数和面试官点评。
- 标准答案只能在完成面试后的报告中返回。
- 每个主问题下按时间顺序展示全部追问、回答和逐轮评价。
- 主问题得分为主回答与追问评分的平均值，综合分为所有主问题平均分。

### FR-07 桌面体验

- 使用 Electron 桌面壳与 React UI。
- 界面适配最小 `1080 × 720`，整体风格清晰、克制、专业。
- 支持拖拽上传、加载状态、错误 Toast、快捷键提交和模型状态提示。
- Electron 必须开启 `contextIsolation`、关闭 `nodeIntegration`、启用沙箱。

### FR-08 文档与版本

- 每个版本同步维护 README、CHANGELOG、需求文档、接口文档和测试。
- 每次发布更新推送到 `concayim/interview-agent` 对应远端分支，并通过 PR 交付。

### FR-09 面试官与领域 Skill

- 面试官 Skill 必须独立声明名称、描述、提示词、开场白、自我介绍邀请语、评价重点和反馈语气。
- 当前提供 Echo 温和教练、Atlas 架构面试官、Vera 压力挑战官、Socrates 启发导师。
- Eino 评价提示和本地降级反馈都必须体现所选面试官风格。
- 领域 Skill 必须声明行业、领域/语言、知识库 ID、主题和出题提示词。
- UI 从 Skill API 动态渲染，不把计算机语言选项写死在选择逻辑中。
- 后续增加金融、制造、医疗等行业时，应以新增 Manifest 和知识库为主要扩展方式。

### FR-10 知识库

- 每个语言 Skill 使用独立知识库，计算机基础使用公共库。
- 初始题库必须种子化进入相应知识库。
- 每次创建面试时，实际选中的题必须写入或更新为 QA，并累计出题次数。
- 支持按题目、答案和标签关键词检索，支持手动新增 QA。
- 本地数据文件以 `0600` 权限原子写入，不写入 Git。

验收：创建 5 题 Go 面试并启用基础库后，Go 库与公共库的出题次数分别增加；检索 `TCP` 只返回相关 QA。

### FR-11 学习中心

- 提供官方文档、文章、视频和课程四类资源。
- 支持从 Go Blog、Inside Java、Spring Blog、Python Insider、Microsoft C++ Team Blog 抓取最新 Feed 元数据。
- 只保存标题、原始链接、来源、短摘要和发布时间，不复制完整正文或视频。
- 支持按领域、内容类型和“我的学习清单”筛选。
- 用户可以把资源加入或移出本地学习清单，点击后在系统浏览器打开原站。
- 单个来源失败时展示部分成功结果，不使整个学习中心不可用。

## 5. 非功能需求

### 安全

- HTTP 服务只监听 `127.0.0.1`。
- Electron 与 Go 服务之间使用每次启动随机生成的访问令牌。
- API Key 不记录到日志，配置文件权限为 `0600`。
- 服务端限制请求体与文件大小，JSON 拒绝未知字段。

### 可用性

- 未配置大模型也能完成完整面试。
- 模型失败自动降级，不丢失用户回答。
- 用户可清楚区分 AI 评价与本地评分。
- 权威 Feed 暂不可用时仍展示内置官方学习资源。
- Electron 每次启动使用独立空闲端口，不得因固定端口被旧进程占用而连接错误后端。
- Skill 目录加载失败时必须展示可见原因和重试入口，不得静默显示空白列表。

### 性能

- 10 MB 以内附件解析不应阻塞其他请求超过合理时间。
- 普通本地评分应在 100 ms 内完成；模型评价与动态追问受外部 API 延迟影响，单轮回答接口超时为 75 秒。

## 6. 数据模型

- `Resume`：文件元信息、提取文本、关键词、创建时间。
- `Question`：语言、难度、题目、标准答案、关键点、标签。
- `Session`：候选人、语言、难度、题目序列、进度、回答、状态和时间。
- `Evaluation`：分数、总结、优点、改进项、评价来源。
- `Report`：整场汇总与含标准答案的逐题记录。
- `Skill`：面试官或领域能力 Manifest。
- `KnowledgeBase / QAItem`：分库元信息、标准 QA、来源和出题次数。
- `LearningResource`：权威内容元数据与本地选择状态。

## 7. 当前不做

- 扫描 PDF OCR；
- 语音识别、语音合成、摄像头或情绪识别；
- 用户账号、云同步、团队管理；
- 历史面试持久化；
- 云端向量知识库与在线题库管理后台。

## 8. 后续里程碑

- `v0.4`：SQLite/全文检索、历史记录、导出复盘报告，并增加首个非计算机行业 Skill。
- `v0.5`：可选 OCR、语音作答与向量检索。
- `v1.0`：多岗位面试模板、可观测性、签名安装包和自动发布。
