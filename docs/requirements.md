# Interview Copilot 需求文档

文档版本：`v0.2.0`

更新日期：`2026-06-23`

## 1. 产品目标

提供一个可扩展到多行业的桌面端模拟面试与学习助手。当前以计算机行业为首个领域：用户上传简历后，系统理解其技术栈，按领域 Skill 和面试官风格 Skill 发起有标准答案的面试；每场结束后，用户可以复盘，并将题目沉淀到可检索知识库。

核心价值是“可练习、可解释、可复盘”，而不只是与大模型闲聊。

## 2. 目标用户

- 正在准备后端、基础架构或综合研发岗位的工程师；
- 希望练习 Golang、Java、Python、C++ 技术表达的候选人；
- 希望根据个人简历进行针对性提问的用户。
- 希望从权威文章、课程和视频持续学习，并建立个人学习清单的用户。

## 3. 用户流程

1. 用户进入准备页，可上传 PDF 或 DOCX 简历。
2. 系统读取附件文本，显示文件状态和识别出的技术关键词。
3. 用户选择行业/领域 Skill、面试官风格 Skill、难度、题目数量并填写称呼。
4. 用户可选择把计算机基础公共库混入语言专项面试。
5. 系统按领域、难度和简历相关性选择题目，并把本次出题记录到对应知识库。
6. 风格化面试官逐题提问；用户可正式作答，也可要求提示、解释、重复题目或跳过。
7. 系统先识别用户意图；只有正式作答或跳过会推进题目，正式作答由 Eino Agent 或本地评分器按所选风格评价。
8. 最后一题完成后生成复盘报告。
9. 用户可在知识库检索/新增 QA，也可在学习中心抓取并选择权威内容。

知识库持久化要求：MySQL 8 保存知识库与 QA 元数据，Milvus 保存向量投影；MySQL 为权威数据源。检索采用关键词召回与向量召回的 RRF 融合，Milvus 不可用时允许降级为 MySQL 关键词结果。

## 4. 功能需求与验收

### FR-01 附件上传与解析

- 支持 `.pdf`、`.docx`，单文件不超过 10 MB。
- 服务端根据扩展名选择解析器，不接受其他格式。
- 解析得到的文本至少 20 个字符；无法读取的扫描版 PDF 给出明确提示。
- 原始临时文件在解析完成或失败后删除。
- 成功响应包含文件名、字符数、内容预览和最多 18 个技术关键词。

验收：上传含 Go、Redis、Docker 的 DOCX 后，响应中能看到对应关键词；上传 TXT 返回 `415`。

### FR-02 简历关键词

- 识别编程语言、框架、数据库、中间件、云原生、工程实践等关键词。
- 关键词按出现次数排序并去重。
- 关键词用于题目相关性排序，不影响题库的标准答案。

### FR-03 技术题库

- 第一版支持 Golang、Java、Python、C++。
- 每种语言至少 6 道题，覆盖基础、进阶、挑战三个难度。
- 每道题必须包含题目、标准答案、关键点和标签。
- 作答前的接口不得返回标准答案和关键点。
- 计算机基础公共库至少提供 6 道题，可混入任意计算机语言 Skill。
- 创建面试应优先从领域 Skill 绑定的知识库 QA 中选题，优先使用出题次数较少并与难度、简历关键词和领域主题相关的记录；知识库无可用 QA 时才回退模型生成题或内置题库。

### FR-04 面试对话

- 支持智能混合面试 3、5、6 题；专项难度当前为 2 题。
- 显示总进度、总计时、题号和题目标签。
- 空回答不能提交，单次回答不超过 8,000 字符。
- 同一题重复提交不得产生两条答案记录。
- 用户输入“提示一下”“换个说法”“重复题目”等短意图时，不应当作正式答案评分，也不推进题目。
- 已配置大模型时，用户输入与当前题无关、闲聊、解释自身状态或表达题目不相关时，应由模型识别为非正式作答并给出面试官式回应。
- 用户明确要求“跳过”时，应记录本题为跳过并进入下一题，复盘中保留该记录。
- 正式回答必须根据知识库标准答案做 0–100 语义相似度评分；低于 75 分时保留当前题并针对最重要的缺失点继续追问，达到 75 分后才进入下一题。
- 细化追问必须接收此前回答作为上下文，并体现所选面试官 Skill 的风格；不得直接泄露标准答案。
- 单次提交回答的后端处理目标为 20 秒以内；前端需要展示意图理解、反馈生成和进度更新流程。

### FR-05 模型接入

- 用户可以配置对话模型的 API Key、Base URL、Model 和启用状态，并独立配置火山语音 API Key、App ID 与 Resource ID。
- 使用 Eino OpenAI ChatModel 对接 OpenAI-compatible API。
- 模型出题必须返回结构化 JSON，包含题目、标准答案、关键点、标签和难度。
- 模型评价必须返回 0–100 语义相似度分、总结、优点、改进项，以及低于 75 分时的单条细化追问。
- 模型意图识别必须返回结构化 JSON，用于区分正式回答、提示/澄清/重复、跳过、偏题和闲聊。
- 模型未配置、超时或返回异常时，面试继续并使用本地关键点评分。
- 提供连接测试接口。
- 火山语音凭据独立于对话模型配置，API Key 不返回前端；未配置时应给出明确提示。

### FR-06 面试复盘

- 显示综合得分、作答数量、总耗时、优点和下一轮重点。
- 每题显示用户回答、标准答案、关键点、分数和面试官点评。
- 标准答案只能在完成面试后的报告中返回。

### FR-07 桌面体验

- 使用 Electron 桌面壳与 React UI。
- 界面适配最小 `1080 × 720`，整体风格清晰、克制、专业。
- 支持拖拽上传、加载状态、错误 Toast、快捷键提交和模型状态提示。
- 支持可选视频面试模式，用户可选择是否开启摄像头，并可使用中文或英文语音输入辅助作答。
- Electron 必须开启 `contextIsolation`、关闭 `nodeIntegration`、启用沙箱。

### FR-12 视频与语音面试

- 准备页允许选择是否开启视频面试，以及中文或英文面试语言；该语言同时控制题目、面试官回复、评价、ASR 和 TTS。
- 开启视频面试后，面试页请求摄像头/麦克风权限并展示本地摄像头预览；权限失败时不阻塞文字面试。
- 语音输入把麦克风音频转换为 16 kHz、16-bit、单声道 PCM，经本地 WebSocket 代理持续发送到火山大模型流式语音识别，不自动提交答案。
- 火山返回的临时完整文本必须实时更新回答框；用户停止录音后等待最终文本，并可编辑后发送。
- 英语模式必须向火山 ASR 发送 `en-US`，要求模型只生成英文题目与反馈，并在模型不可用时提供全英文的本地题目、提示、跳题和评分反馈。
- 本地服务使用火山 `bigmodel_async` WebSocket 协议，语音 API Key 只允许保存在服务端配置文件中。
- 支持豆包 TTS 自动朗读面试官开场、题目、追问、评价摘要和下一题；TTS 失败不得阻塞文字面试。
- 开始 ASR 录音前必须停止 TTS 播放，避免扬声器回声进入候选人转写。
- 面试页提供 TTS 静音和题目重播控制；ASR 与 TTS 凭据、Resource ID 必须独立配置。

### FR-08 文档与版本

- 每个版本同步维护 README、CHANGELOG、需求文档、接口文档和测试。
- 每次发布更新推送到 `concayim/interview-agent` 对应远端分支，并通过 PR 交付。

### FR-09 面试官与领域 Skill

- 面试官 Skill 必须独立声明名称、描述、提示词、开场白、评价重点和反馈语气。
- 当前提供 Echo 温和教练、Atlas 架构面试官、Vera 压力挑战官、Socrates 启发导师。
- Eino 评价提示和本地降级反馈都必须体现所选面试官风格。
- 领域 Skill 必须声明行业、领域/语言、知识库 ID、主题和出题提示词。
- UI 从 Skill API 动态渲染，不把计算机语言选项写死在选择逻辑中。
- 后续增加金融、制造、医疗等行业时，应以新增 Manifest 和知识库为主要扩展方式。

### FR-10 知识库

- 每个语言 Skill 使用独立知识库，计算机基础使用公共库。
- 初始题库必须种子化进入相应知识库。
- 每次创建面试时，实际选中的题必须写入或更新为 QA，并累计出题次数。
- 支持按题目、答案和标签关键词检索，支持手动新增 QA。
- 本地数据文件以 `0600` 权限原子写入，不写入 Git。

验收：创建 5 题 Go 面试并启用基础库后，Go 库与公共库的出题次数分别增加；检索 `TCP` 只返回相关 QA。

### FR-11 学习中心

- 提供官方文档、文章、视频和课程四类资源。
- 支持从 Go Blog、Inside Java、Spring Blog、Python Insider、Microsoft C++ Team Blog 抓取最新 Feed 元数据。
- 只保存标题、原始链接、来源、短摘要和发布时间，不复制完整正文或视频。
- 支持按领域、内容类型和“我的学习清单”筛选。
- 用户可以把资源加入或移出本地学习清单，点击后在系统浏览器打开原站。
- 单个来源失败时展示部分成功结果，不使整个学习中心不可用。

## 5. 非功能需求

### 安全

- HTTP 服务只监听 `127.0.0.1`。
- Electron 与 Go 服务之间使用每次启动随机生成的访问令牌。
- API Key 不记录到日志，配置文件权限为 `0600`。
- 服务端限制请求体与文件大小，JSON 拒绝未知字段。

### 可用性

- 未配置大模型也能完成完整面试。
- 模型失败自动降级，不丢失用户回答。
- 用户可清楚区分 AI 评价与本地评分。
- 权威 Feed 暂不可用时仍展示内置官方学习资源。

### AI 形象实时问答

- 面试过程中显示本地 VRM 3D 面试官形象，不依赖外部模型 CDN。
- 形象状态与实时语音识别、回答评估和 TTS 播放同步，支持空闲、聆听、思考和说话四种状态。
- 形象渲染或 TTS 失败不得阻断文字问答。
- 对话会话只由现有 Go 面试服务维护，不通过 iframe 接入独立聊天应用。
- 默认模型授权与来源必须随安装包分发，并在形象舞台提供署名入口。

### 性能

- 10 MB 以内附件解析不应阻塞其他请求超过合理时间。
- 普通本地评分应在 100 ms 内完成；模型评价受外部 API 延迟影响，超时为 45 秒。

## 6. 数据模型

- `Resume`：文件元信息、提取文本、关键词、创建时间。
- `Question`：语言、难度、题目、标准答案、关键点、标签。
- `Session`：候选人、语言、难度、题目序列、进度、回答、状态和时间。
- `Evaluation`：分数、总结、优点、改进项、评价来源。
- `Report`：整场汇总与含标准答案的逐题记录。
- `Skill`：面试官或领域能力 Manifest。
- `KnowledgeBase / QAItem`：分库元信息、标准 QA、来源和出题次数。
- `LearningResource`：权威内容元数据与本地选择状态。

## 7. 当前不做

- 扫描 PDF OCR；
- 声纹确认、摄像头情绪识别和完整音视频分析；
- 用户账号、云同步、团队管理；
- 历史面试持久化；
- 云端向量知识库与在线题库管理后台。

## 8. 后续里程碑

- `v0.3`：SQLite/全文检索、历史记录、导出复盘报告，并增加首个非计算机行业 Skill。
- `v0.4`：可选 OCR、ModelScope CAM++ 声纹服务端适配、追问机制与向量检索。
- `v1.0`：多岗位面试模板、可观测性、签名安装包和自动发布。
